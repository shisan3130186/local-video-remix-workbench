# 总体开发框架

## 一、项目最终形态

本项目最终形态是一个本地桌面端短视频批量混剪工作台。

它服务的用户是：

1. 有大量视频素材，需要批量处理的用户。
2. 做短视频矩阵号，需要快速生成多个版本视频的用户。
3. 希望素材留在本地，不想上传到云端处理的用户。
4. 不需要专业精剪，只需要稳定批量处理流程的用户。

它要解决的问题是：

1. 视频素材多，人工逐个剪辑效率低。
2. 普通剪辑软件更适合单条精剪，不适合批量混剪。
3. 用户需要从素材导入到批量导出形成固定流程。
4. 后续需要接入字幕、TTS、AI 内容理解、会员和 API Key 管理。

本项目不是复制竞品 UI，也不是一次性做完整竞品。开发原则是先做可运行 MVP，再逐步扩展。

## 二、核心业务流程

完整业务流程：

```text
启动软件
  ↓
检测 FFmpeg / FFprobe 环境
  ↓
导入素材
  ↓
过滤可用视频文件
  ↓
读取视频信息
  ↓
生成素材列表
  ↓
用户预览视频
  ↓
用户选择处理方式
  ↓
视频切片
  ↓
混剪组合
  ↓
字幕 / TTS / 音频处理
  ↓
创建导出任务
  ↓
任务队列执行
  ↓
FFmpeg 导出视频
  ↓
记录任务日志
  ↓
用户查看导出结果
```

V0.1 只做最小闭环：

```text
FFmpeg 检测 → 导入素材 → 读取信息 → 视频预览 → 基础导出 → 任务日志
```

## 三、核心模块

### 1. 首页 / 工作台模块

作用：
作为软件主入口，展示素材列表、预览区域、环境状态、输出设置、任务进度和日志。

V0.1 是否必须做：
必须做，但只在已有首页基础上补齐状态和入口，不做 UI 大重构。

依赖：
素材导入模块、视频预览模块、视频信息读取模块、任务队列模块。

暂时不做：
复杂首页入口矩阵、会员入口、AI 功能入口、竞品式 UI。

### 2. 素材导入模块

作用：
支持单视频导入和文件夹导入，过滤非视频文件，形成可处理素材列表。

V0.1 是否必须做：
必须做。

依赖：
Tauri 文件选择能力、视频信息读取模块。

暂时不做：
素材云同步、复杂素材库、智能去重、自动分类。

### 3. 视频预览模块

作用：
点击素材后可以播放、暂停、切换预览视频。

V0.1 是否必须做：
必须做。

依赖：
素材导入模块、前端 video 播放能力、本地路径转换能力。

暂时不做：
时间线剪辑、逐帧预览、多轨预览、波形图。

### 4. 视频信息读取模块

作用：
通过 FFprobe 读取视频时长、分辨率、帧率、是否有音频等信息。

V0.1 是否必须做：
必须做。

依赖：
FFprobe 环境检测、VideoEngine。

暂时不做：
画面内容理解、字幕识别、镜头识别、人物识别。

### 5. 视频处理引擎模块

作用：
统一封装 FFmpeg / FFprobe 调用，是所有视频处理能力的唯一入口。

V0.1 是否必须做：
必须做。

依赖：
Tauri command、FFmpeg、FFprobe、任务队列。

暂时不做：
复杂滤镜库、GPU 策略、多引擎切换。

### 6. 视频切片模块

作用：
把视频按固定时长、随机区间或规则切成片段，供混剪使用。

V0.1 是否必须做：
不做，放到 V0.2。

依赖：
视频信息读取模块、视频处理引擎模块、任务队列模块。

暂时不做：
场景切割、AI 镜头识别切割。

### 7. 混剪生成模块

作用：
按规则抽取、排序、拼接片段，生成新视频。

V0.1 是否必须做：
不做，放到 V0.2。

依赖：
视频切片模块、视频处理引擎模块、任务队列模块。

暂时不做：
分类混剪、AI 自动选片、多模板批量生成。

### 8. 音频 / BGM 模块

作用：
控制原声保留、静音、替换 BGM、音量调整。

V0.1 是否必须做：
不做。

依赖：
视频处理引擎模块、任务队列模块。

暂时不做：
自动踩点、音乐节奏分析、批量 BGM 匹配。

### 9. 字幕模块

作用：
添加字幕、管理字幕样式、后续支持字幕烧录到视频。

V0.1 是否必须做：
不做，放到 V0.3。

依赖：
视频处理引擎模块、TTS 模块、后续 ASR 模块。

暂时不做：
ASR 自动字幕、动态字幕、高级字幕模板。

### 10. TTS 模块

作用：
把文案转换成语音，后续与视频时长匹配。

V0.1 是否必须做：
不做，放到 V0.3。

依赖：
API Key 模块、任务队列模块、音频模块。

暂时不做：
多平台 TTS、声音克隆、复杂配音模板。

### 11. 任务队列模块

作用：
管理耗时任务，包括视频信息读取、导出、后续切片和混剪。

V0.1 是否必须做：
必须做基础版。

依赖：
VideoEngine、日志模块、前端状态展示。

暂时不做：
多任务并发、暂停恢复、失败自动重试。

### 12. 设置模块

作用：
保存 FFmpeg 路径、默认输出目录、导出格式等基础配置。

V0.1 是否必须做：
只做极简配置。

依赖：
本地配置存储、环境检测模块。

暂时不做：
账户设置、云端设置、多套配置。

### 13. API Key 模块

作用：
后续管理 TTS、ASR、AI 文案等第三方服务的 API Key。

V0.1 是否必须做：
不做。

依赖：
安全存储、设置模块、服务调用模块。

暂时不做：
API Key 输入、保存、校验、调用。

### 14. 会员卡密模块

作用：
后续用于软件授权、功能解锁、有效期管理。

V0.1 是否必须做：
不做。

依赖：
远程校验服务、本地缓存、设备绑定策略。

暂时不做：
会员、卡密、支付、激活。

### 15. 日志和异常处理模块

作用：
记录环境检测、导入、信息读取、导出任务中的成功和失败原因。

V0.1 是否必须做：
必须做基础版。

依赖：
任务队列模块、VideoEngine、前端日志展示。

暂时不做：
日志上传、远程诊断、复杂错误分析。

## 四、V0.1 最小闭环

│  ├─ stores

目录原则：

1. 页面组件只负责展示和触发动作。
2. 前端 Service 只调用 Tauri command。
3. FFmpeg / FFprobe 调用必须集中在 VideoEngine。
4. 任务进度和日志必须通过任务队列管理。
5. 不要为了 V0.1 过度拆分目录。

## 六、核心技术边界

前端负责：
界面展示、用户交互、视频列表、预览、状态提示、日志展示。

Tauri 负责：
文件选择、本地路径访问、调用后端命令、连接前端和本地系统能力。

FFmpeg / FFprobe 负责：
视频信息读取、转码、导出、后续切片、拼接、字幕、音频处理。

VideoEngine 负责：
统一封装 FFmpeg / FFprobe，禁止页面组件直接拼命令。

TaskQueue 负责：
把耗时操作变成任务，记录状态、进度、日志和错误。

SQLite 后续负责：
保存素材记录、视频信息、任务记录、导出记录、用户设置、混剪模板、字幕样式等。

API Key 后续保存原则：
不允许明文保存。优先使用系统安全存储。数据库只保存服务商、名称、状态等非敏感信息。

会员卡密后续原则：
不能纯本地判断。必须有远程校验、有效期校验、设备绑定或服务端签名。本地只做缓存。

## 七、开发顺序

V0.1 推荐拆成 10 个小任务：

1. FFmpeg / FFprobe 环境检测。
2. 建立 VideoEngine 基础入口。
3. 单视频导入。
4. 文件夹导入。
5. 视频信息读取。
6. 视频预览。
7. 输出目录选择。
8. 基础导出。
9. 任务进度展示。
10. 日志和错误提示整理。

每个任务都必须：

1. 只做一个功能。
2. 有明确验收标准。
3. 可单独 Git 提交。
4. 不依赖太多未完成内容。

## 八、主要风险

1. UI 做好了但功能跑不通。
2. FFmpeg 命令散落在页面里。
3. 任务队列不稳定。
4. API Key 明文保存。
5. 会员系统写成纯本地判断。
6. 重复开发已经完成的内容。
7. 版本范围失控。
8. 过早引入复杂数据库结构。
9. Windows 中文路径和空格路径处理失败。
10. 大文件处理时界面卡死。

## 九、当前结论

当前最重要的事情不是继续扩展功能，而是先把 V0.1 的最小闭环跑通。

下一步开发应该从 FFmpeg / FFprobe 环境检测开始。
