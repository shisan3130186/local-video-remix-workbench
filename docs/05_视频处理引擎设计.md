# 视频处理引擎设计

> 文档定位：下方版本规划保留为历史设计基线。当前 AI 智能混剪仍严格复用本文件定义的 VideoEngine 边界，AI 只负责画面理解和分镜规划，不在前端直接拼接 FFmpeg 命令。

## 目标

所有视频处理统一通过 VideoEngine 调用，禁止页面组件直接拼接 FFmpeg 命令。

VideoEngine 是本项目最核心的技术边界。页面组件只传入用户选择和参数，不关心 FFmpeg 命令怎么拼。

## 模块

### VideoProbeService

负责：
- 检测 ffmpeg
- 检测 ffprobe
- 读取视频时长
- 读取分辨率
- 读取帧率
- 读取音频信息

V0.1 必须做：

1. 检测 ffmpeg 是否存在。
2. 检测 ffprobe 是否存在。
3. 返回 ffmpeg 版本号。
4. 返回 ffprobe 版本号。
5. 读取视频基础信息。

暂时不做：

1. 画面内容识别。
2. 字幕识别。
3. 镜头识别。

### VideoImportService

负责：
- 单文件导入
- 文件夹导入
- 视频格式过滤
- 文件路径管理

V0.1 必须做：

1. 单视频导入。
2. 文件夹导入。
3. 过滤非视频文件。
4. 保留原始文件路径。

暂时不做：

1. 素材云同步。
2. 智能去重。
3. 自动分类。

### VideoRenderService

负责：
- 基础导出
- 格式转换
- 分辨率处理
- 错误捕获

V0.1 必须做：

1. 把一个导入视频导出成新的 mp4。
2. 支持选择输出目录。
3. 返回导出结果。
4. 捕获失败原因。

暂时不做：

1. 复杂滤镜。
2. 多版本批量导出。
3. GPU 加速策略。

### VideoSplitService

负责：
- 固定时长切片
- 场景变化智能切片
- 最短/最长片段保护
- 为AI理解准备多帧画面

当前实现：固定时长模式继续使用FFmpeg segment分段；智能模式先用 `select=gt(scene,阈值)` 和 `showinfo` 获取候选转场，再过滤会产生过短片段的切点，并对过长连续镜头补切。关键帧分段统一允许0.05秒时间容差，避免不同FFmpeg版本因时间基误差漏切。每个切片最多抽取开头、中间、结尾3帧，AI综合理解后只缓存代表图和最终描述。

当前补充规则：切片开始前由Rust确认输出目录真实存在；前端路径文字不为空不能代替文件系统检查。原始素材封面使用固定320×240完整画面模式，AI分析预览图保持源比例。前端不得直接拼接场景检测或分段命令。

### VideoMixService

负责：
- 随机抽取片段
- 拼接片段
- 批量生成

V0.1 不做。

计划：

1. V0.2 做基础随机混剪。
2. V0.4 做分类混剪。
3. V0.6 再考虑 AI 辅助选片。

## 推荐返回格式

所有 VideoEngine 方法建议返回结构化结果，不要只返回字符串。

示例：

```text
成功结果：
{
  success: true,
  data: 具体结果,
  message: "操作成功"
}

失败结果：
{
  success: false,
  errorCode: "错误代码",
  message: "给用户看的错误说明",
  detail: "给开发者看的详细错误"
}
```

## FFmpeg 调用规则

必须遵守：

1. 所有 FFmpeg / FFprobe 调用集中在 VideoEngine。
2. 页面组件不能拼接命令。
3. Service 层不能散写重复命令。
4. 命令参数必须来自明确的结构化参数。
5. 文件路径要支持中文和空格。
6. 错误信息要能返回给任务日志。

## V0.1 VideoEngine 最小能力

V0.1 只需要支持：

1. 检测 ffmpeg。
2. 检测 ffprobe。
3. 读取视频基础信息。
4. 基础导出。
5. 返回进度和错误信息。

## 后续扩展能力

### TTS第一阶段边界

当前TTS第一阶段只由Rust网络模块生成本地MP3，不修改视频文件，因此不进入VideoEngine混音流程。后续实现“配音加入视频”时，原声音量调整、配音轨道、BGM混音、镜头时长适配和最终编码必须统一放入VideoEngine，前端不得拼接FFmpeg命令。

### TTS第二阶段边界

TTS第二阶段新增独立 `narrated_mix` 模块。每个AI分镜输入主视频、备选视频和临时配音路径，VideoEngine读取真实配音时长：画面较长时裁短，主画面较短时先换用可安全适配的较长备选画面，再允许最多8%轻微减速和约0.8秒尾帧补齐。超过安全范围时直接报错，禁止连续数秒冻结最后一帧。原片段声音默认关闭；用户主动开启后，VideoEngine会检测实际选中画面的音轨、按相同轻微速度和指定音量混入，无音轨时自动退回纯AI配音。处理后的分镜继续交给现有混剪引擎，因此画布、效果、画中画、平滑混剪和BGM继续生效。

当前限制：
1. 配音视频只支持1.0x速度。
2. 原片段声音默认关闭，可选0%～100%混合，默认15%；不做人声与BGM分离。
3. 自动字幕只支持分镜内自然短句，不做逐字时间轴。
4. 不做声音克隆和批量多音色。

### 自动字幕第一阶段边界

自动字幕只接入逐句AI配音视频。`subtitle`模块根据分镜文字和配音时长生成ASS文件，优先按标点拆成自然短句，没有标点的长文案按可读长度拆分，再按有效字符数分配显示时间。支持顶部、中间、底部位置和小、标准、大字号。字幕在临时配音分镜阶段烧录，因此后续画布、特效、画中画、平滑混剪、原声和BGM继续走原有VideoEngine链路。

当前限制：
1. 只生成分镜内短句字幕，不做逐字时间轴或词级精确对齐。
2. 不识别原视频语音，不调用ASR。
3. 默认使用微软雅黑；FFmpeg必须包含libass的 `ass` 滤镜。
4. 不支持复杂动画、颜色编辑、描边编辑或字幕模板。

### 云端ASR音频标准化边界

原始音频和带声音视频统一进入 `video_engine/audio.rs`。VideoEngine先调用FFprobe确认存在声音轨并读取时长，再转为16kHz单声道24kbps MP3交给Rust ASR网络模块。转换过程接入统一任务进度和取消；临时MP3由任务临时目录自动清理。

当前限制：
1. 单个文件不超过2小时。
2. 标准化音频超过24MB时要求先分段。
3. 前端只能传文件路径和任务上下文，不得拼FFmpeg命令。
4. ASR只输出完整文字和句子时间轴，暂不直接烧录字幕。

### 水印工具第一版边界

文字水印和图片水印统一由`video_engine/watermark.rs`生成结构化滤镜。文字先写入任务临时目录中的UTF-8文本文件，再由FFmpeg `drawtext`使用Windows系统字体读取；图片作为循环输入流，经透明度、相对宽度缩放和`overlay`叠加。原水印处理由`video_engine/watermark_removal.rs`生成：边缘裁剪移除顶部或底部水印带后保持比例放大铺满，融合修复使用`delogo`，固定区域模糊和马赛克裁剪处理后覆盖回原画面，固定色块使用`drawbox`。移动模式保存2～8个带时间的位置，Rust对相邻位置做线性插值；动态模糊和马赛克使用移动`crop`后动态`overlay`，动态色块使用透明`color`图层配合动态`overlay`。`mix.rs`按画中画、图片水印和BGM是否启用动态分配输入编号，所有成片只做一次最终编码。

当前限制：
1. 添加的新文字和图片水印仍为静态，不做动画、滚动、随机移动或按时间出现。
2. 固定处理支持五个位置；边缘裁剪只支持四个边角对应的顶部/底部，不支持居中。
3. 文字字体优先使用微软雅黑，系统字体缺失时明确报错。
4. 固定处理顺序为基础画面、处理原水印、画中画、添加新水印和输出；水印必须与画布、画面效果、BGM和输出编码共享同一VideoEngine链路。
5. 移动处理只支持模糊、马赛克和色块遮盖，不支持移动`delogo`与边缘裁剪。
6. 移动处理只允许“原画”画布的当前完整视频导出；普通、分类、批量、AI和配音混剪必须拒绝该设置。
7. 第一版由用户手动设置关键位置，不做自动识别、AI无痕修复或自动目标跟踪；不引入OpenCV和本地AI模型。
