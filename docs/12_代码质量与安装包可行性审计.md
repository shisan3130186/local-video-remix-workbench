# 代码质量与 Windows 安装包可行性审计

审计日期：2026-07-13

## 一、结论

项目不是需要推倒重写的“屎山”，但已经从早期 MVP 进入必须控制技术债的阶段。

当前评价：

| 项目 | 评价 | 结论 |
|---|---:|---|
| 分层与模块边界 | 7/10 | Vue Service、Tauri command、Rust VideoEngine 边界基本清楚 |
| 日常维护难度 | 5/10 | `App.vue`、`styles.css`、`mix.rs` 已成为明显热点 |
| 自动测试 | 4/10 | AI 与工具路径有测试，前端和视频混剪缺少自动测试 |
| 内部安装包可行性 | 7/10 | NSIS 安装器已经成功生成，但测试电脑仍需 FFmpeg 和 AI 环境变量 |
| 外部普通用户可用性 | 3/10 | 未内置 FFmpeg、没有用户级 AI 配置、安装包未签名 |

结论分两层：

1. 可以继续在现有项目上添加功能，不需要重写。
2. 当前安装器适合开发者或懂配置的内部测试人员，不适合直接发给普通外部用户。

## 二、代码质量证据

主要大文件：

| 文件 | 行数 | 风险 |
|---|---:|---|
| `src/styles.css` | 7行入口（重构前3148行） | 样式已按原顺序拆入7个文件，单文件最大约717行 |
| `src/App.vue` | 约825（重构前为2095） | 主要业务流程已迁出，后续新功能继续通过独立模块接入 |
| `src-tauri/src/video_engine/mix.rs` | 约 730 | 画布、特效、画中画、BGM、字幕边界和 FFmpeg 参数集中 |
| `src/components/ToolSettingModal.vue` | 约174（重构前654行） | 保留弹窗外壳和调度，具体设置已拆成独立面板 |
| `src-tauri/src/ai_remix.rs` | 约 579 | 请求、提示词、解析、校验和测试集中，但当前仍可控 |

好的部分：

1. 页面没有直接拼 FFmpeg 命令。
2. 视频处理集中在 Rust VideoEngine。
3. AI Key 只在 Rust 环境变量中读取。
4. AI 返回值有严格 JSON 校验。
5. TypeScript Service 基本只承担 Tauri 调用和类型边界。
6. Rust `cargo clippy --all-targets -- -D warnings` 已通过。

需要逐步治理的部分：

1. 后续每增加一个大功能，都应优先拆出 composable / service，不再继续扩大 `App.vue`。
2. 新增界面样式应按组件拆分，不继续无限追加到全局 `styles.css`。
3. `mix.rs` 后续应按视频、音频、画中画和字幕滤镜构建器逐步拆分。
4. 增加前端业务测试和 VideoEngine 参数构建测试。

禁止做法：一次性重写三个大文件。正确方式是每开发一个新功能，顺手迁出与该功能直接相关的一小块。

## 五、发测试用户前的阻塞项

### P0：必须解决

1. 内置 FFmpeg / FFprobe，并确认所选构建版本和许可证允许分发。
2. 在 `tauri.conf.json` 中把合法 FFmpeg 文件加入安装包资源。
3. 选择 AI 凭证方案：
   - 内部小范围测试：在每台测试电脑手动配置环境变量。
   - 用户使用自己的 Key：增加设置界面，并存入 Windows 安全凭据，不写普通文件。
   - 面向普通用户：自建服务端代理，由服务端保管平台 Key、鉴权、限额和计费。
4. 在没有源码、没有开发环境、没有 FFmpeg 的干净 Windows 电脑完整验收。

### P1：正式公开测试前建议解决

1. 准备正式 Logo 和多尺寸图标。
2. 购买或配置 Windows 代码签名证书，减少 SmartScreen 拦截。
3. 收窄 Tauri `assetProtocol.scope`；当前 `**/*` 范围过宽。
4. 增加版本号、隐私说明、用户协议和第三方许可证说明。
5. 增加临时切片清理、磁盘空间提示和失败恢复。

## 六、推荐执行顺序

1. 先确定测试对象是内部人员还是普通外部用户。
2. 准备合法的 FFmpeg / FFprobe 分发文件并完成内置。
3. 确定 AI Key 使用方案。
4. 做首次启动环境检查页面。
5. 在干净电脑安装并完成主链路。
6. 收集 10 轮稳定性测试数据。
7. 再开始添加用户确认的基础功能。
