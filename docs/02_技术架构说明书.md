# 技术架构说明书

> 文档定位：下方 V0.1 内容是初始架构基线。当前项目已经在相同分层和 VideoEngine 边界上完成 AI 文案智能混剪 MVP；最新状态和安全约束以根目录 `README.md`、`PROJECT_STATUS.md`、`DECISIONS.md` 为准。

## 架构原则

前端只负责界面和用户交互。
视频处理必须走统一 VideoEngine。
耗时任务必须走任务队列。
API Key 不允许明文保存。
会员卡密不允许纯本地判断。

当前阶段先做 V0.1 基础可运行版，目标是打通：

```text
FFmpeg 检测 → 导入素材 → 读取信息 → 视频预览 → 基础导出 → 任务日志
```

## 模块划分

- UI 层：页面和组件
- Service 层：业务逻辑
- VideoEngine 层：FFmpeg / FFprobe 封装
- Task 层：任务队列、进度、日志
- Storage 层：SQLite / 本地配置

## 分层说明

### 1. UI 层

负责：

1. 页面展示。
2. 用户点击、选择、输入。
3. 视频列表展示。
4. 视频预览展示。
5. 任务状态展示。
6. 错误提示展示。

禁止：

1. 直接拼接 FFmpeg 命令。
2. 直接处理复杂视频逻辑。
3. 直接保存 API Key 明文。

### 2. Service 层

负责：

1. 组织前端业务流程。
2. 调用 Tauri command。
3. 整理 UI 需要的数据格式。
4. 管理前端状态。

说明：
Service 层可以理解为页面和本地能力之间的中间层。页面只告诉 Service 用户想做什么，Service 再去调用后端能力。

当前前端按功能逐步收拢到 `src/features`。AI混剪位于 `src/features/ai-remix`；素材导入、封面和切片位于 `src/features/materials`；基础导出、随机混剪、分类混剪和批量生成位于 `src/features/remix-export`。各功能由组件负责展示、composable负责状态和流程、Service负责Tauri调用，专用逻辑不再散落在 `App.vue`。

素材封面与AI片段预览使用不同缩略图模式：素材库封面由Rust生成固定画布的完整画面版本，AI图片理解预览保持源比例。智能切片由Rust VideoEngine扫描场景变化候选点，并结合最短/最长片段时长整理安全切点；固定时长模式继续保留。每个新片段最多抽取15%、50%、85%位置的3帧供AI综合理解，界面显示中间代表图，最终画面描述写入SQLite缓存。切片前必须验证输出目录真实存在，错误同时进入任务日志和核心流程提示。

设置弹窗由 `src/components/ToolSettingModal.vue` 统一保持对外接口，具体画布、转场、画中画、BGM、视频效果等面板位于 `src/components/tool-settings`。全局样式入口仍为 `src/styles.css`，实际规则按原始级联顺序拆入 `src/styles`，避免后续新增功能继续堆入单个大文件。

TTS第一阶段位于 `src/features/tts`，前端组件负责展示配置状态和播放结果，composable负责生成状态和日志，Service只调用Tauri命令。Rust `tts.rs`负责读取火山语音Key、发送请求、解析分块响应和保存MP3。TTS Key不进入前端；后续配音加入视频时仍必须通过VideoEngine处理。

TTS第二阶段继续由 `src/features/tts` 组织逐句请求、原声开关、原声音量和进度。Rust `tts.rs`把每句语音写入安全临时目录；`video_engine/narrated_mix.rs`读取真实配音时长，画面较长时裁短，主画面较短时优先换用更长备选片段，再允许最多8%轻微减速和约0.8秒安全补帧，超过范围直接报错。原片段声音默认不进入输出；用户主动开启原声后，VideoEngine检测实际选中画面的音轨并按相同轻微速度和指定音量与AI配音混合，无音轨时自动退回纯AI配音。临时分镜最后交给现有混剪引擎处理画布、效果、画中画、平滑混剪和BGM。

自动字幕第一阶段继续由 `src/features/tts` 保存配音视频字幕开关、位置和字号。每个分镜把对应文案作为字幕文字交给Rust；`video_engine/subtitle.rs`生成与配音同长的临时ASS字幕，处理中文转义、两行换行、长句字号收缩和位置映射。`narrated_mix.rs`在临时配音分镜中调用FFmpeg `ass`滤镜完成烧录，临时ASS随会话目录清理。普通无配音混剪的旧字幕占位接口保持禁用，不在本阶段扩展。

配音画面时长适配由Rust本地断句、AI画面匹配和VideoEngine共同负责。Rust先按标点和长度生成固定短分镜；AI只为每个 `shotIndex` 选择主画面和较长备选画面，不得修改文案。备选片段与其他主片段冲突时自动清理，真正的未知编号、遗漏分镜和重复主片段仍严格拒绝。前端只传递结构化候选数据；`narrated_mix.rs`读取真实配音和视频时长，主画面不足时自动尝试备选画面，只允许最多8%轻微减速和约0.8秒尾帧补齐。超过安全范围时返回明确错误，禁止继续无限复制最后一帧。

### 3. Tauri 层

负责：

1. 文件选择。
2. 本地路径访问。
3. 调用本地命令。
4. 连接前端和本地系统能力。
5. 向前端返回结构化结果。

说明：
Tauri 是前端和电脑本地能力之间的桥。

### 4. VideoEngine 层

负责：

1. 检测 FFmpeg / FFprobe。
2. 读取视频信息。
3. 基础导出。
4. 后续切片、拼接、字幕、音频处理。

禁止：

1. 让页面组件绕过 VideoEngine 直接调用 FFmpeg。
2. 把同一种 FFmpeg 调用散落在多个地方。

### 5. Task 层

负责：

1. 管理耗时任务。
2. 记录任务状态。
3. 记录任务进度。
4. 记录任务日志。
5. 记录失败原因。

V0.1 只做单任务顺序执行，不做复杂并发。

### 6. Storage 层

负责：

1. 保存用户设置。
2. 后续保存素材记录。
3. 后续保存任务记录。
4. 后续保存导出记录。
5. 后续保存混剪模板和字幕样式。

说明：
V0.1 可以先不强行引入复杂数据库结构，但代码结构要给 SQLite 留位置。

当前项目恢复第一版补充：
1. `src/features/project-recovery` 负责前端快照状态、自动保存节流、恢复弹窗和失效路径降级。
2. Rust `project_snapshot.rs` 负责快照版本、大小、敏感字段、文件读写和路径存在性检查。
3. 第一版只保存最近一个项目的版本化JSON，不修改SQLite结构；后续多项目管理再迁入数据库。
4. 项目快照和API密钥配置完全分离，快照禁止包含Key、密码、凭证或secret字段。
5. 快照只保存路径和编辑状态，不复制素材、切片、配音或成片。

## 数据边界

### 视频素材信息

建议字段：

1. 文件路径。
2. 文件名。
3. 文件大小。
4. 视频时长。
5. 分辨率。
6. 帧率。
7. 是否有音频。
8. 导入时间。

### 任务信息

建议字段：

1. 任务 ID。
2. 任务类型。
3. 任务状态。
4. 输入文件。
5. 输出文件。
6. 进度。
7. 日志。
8. 错误信息。
9. 开始时间。
10. 结束时间。

### 设置项

建议字段：

1. FFmpeg 路径。
2. FFprobe 路径。
3. 默认输出目录。
4. 默认导出格式。
5. 日志保留策略。

## API Key 安全原则

后续 API Key 不能明文保存到普通文件、日志或数据库明文字段。

推荐方向：

1. 优先使用系统安全存储。
2. 数据库只保存服务商、名称、状态、创建时间等非敏感信息。
3. 日志中永远不输出完整 API Key。

## 会员卡密原则

会员卡密不能只靠本地判断。

原因：
如果完全写在本地，用户可以通过修改配置、数据库或代码绕过校验。

后续应该考虑：

1. 远程校验。
2. 有效期校验。
3. 设备绑定。
4. 服务端签名。
5. 本地只做状态缓存。

## V0.1 技术边界

V0.1 只允许围绕基础可运行闭环开发：

1. FFmpeg / FFprobe 环境检测。
2. 视频导入。
3. 视频信息读取。
4. 视频预览。
5. 输出目录选择。
6. 基础导出。
7. 任务进度和日志。

V0.1 不开发：

1. 会员系统。
2. API Key 系统。
3. AI 内容理解。
4. TTS。
5. ASR 字幕识别。
6. 高级去水印。
7. 复杂画中画。
8. 云端渲染。
9. 支付系统。
